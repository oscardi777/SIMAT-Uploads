Conceptos previos

¿Qué son ARIMA, SARIMA y SARIMAX? Teoría

Antes de entrar al código es importante entender qué hace cada modelo y por qué los tres tienen sentido para tu problema de consumo eléctrico diario.

ARIMA

AutoRegressive Integrated Moving Average. Modela la serie usando sus propios valores pasados (AR), la diferenciación para estacionarizarla (I) y los errores pasados (MA). No entiende de estacionalidad.

SARIMA

ARIMA + componente Seasonal. Añade un segundo bloque (P, D, Q, m) que captura patrones que se repiten cada m periodos. Ideal cuando el consumo sube/baja cada semana.

SARIMAX

SARIMA + variables eXógenas. Puede incorporar tus 11 columnas adicionales (día de semana, festivos, mantenimientos…) como información extra para mejorar la predicción.

En tu dataset, el consumo eléctrico de la estación probablemente tiene un patrón semanal (más consumo entre semana, menos los fines de semana) y puede verse afectado por eventos como festivos o mantenimientos. Eso hace que SARIMA y SARIMAX sean los candidatos más fuertes.

¿Por qué no usar solo SARIMAX?
Siempre es bueno comparar los tres. A veces las variables exógenas añaden ruido en lugar de señal. El notebook evalúa los tres y deja que las métricas decidan.

La notación formal de los parámetros que vamos a tunear es:

ARIMA(p, d, q) — SARIMA(p, d, q)(P, D, Q)[m] — SARIMAX(p, d, q)(P, D, Q)[m] + X
ParámetroNombreQué controlaEjemplo intuitivo
pAR order¿Cuántos días pasados de consumo usar?p=2 → usa consumo de ayer y anteayer
dIntegration¿Cuántas veces diferenciar para quitar tendencia?d=1 → trabaja con el cambio diario de consumo
qMA order¿Cuántos errores pasados incluir?q=1 → corrige usando el error de ayer
PSeasonal ARComo p, pero con saltos de m periodosP=1, m=7 → usa consumo del mismo día la semana pasada
DSeasonal IDiferenciación estacionalD=1, m=7 → quita la tendencia semanal
QSeasonal MAErrores estacionales pasadosQ=1, m=7 → corrige usando error del mismo día semana pasada
mSeasonalityCada cuántos periodos se repite el patrónm=7 para patrón semanal en datos diarios

Definición dinámica de splits Celdas 8–9

Esta es una de las secciones más importantes. Aquí se construye la lógica de cómo se divide el tiempo en Train, Folds CV y Test.

Train
2018-01 → antes del TEST_START Datos para aprender
Folds CV (dentro de train)
Últimos N_CV_FOLDS meses Para elegir parámetros
Test
TEST_START → fin Evaluación final bloqueada
splits
def month_row_count(period, dataframe):
    start = pd.Timestamp(str(period) + '-01')
    end   = start + pd.offsets.MonthEnd(1)
    return len(dataframe[(dataframe.index >= start) &
                          (dataframe.index <= end)])

# Meses de test: ≥ 20 días de datos
TEST_MONTHS = []
while p <= last_period:
    if month_row_count(p, df) >= 20:
        TEST_MONTHS.append(str(p))
    p += 1

# Folds CV: últimos N_CV_FOLDS meses del train
CV_MONTHS = []
while len(CV_MONTHS) < N_CV_FOLDS:
    if month_row_count(p, df) >= 20:
        CV_MONTHS.insert(0, str(p))
    p -= 1

¿Por qué se filtra por meses completos (≥ 20 días)? Si el último mes del dataset tiene solo 5 días, incluirlo como mes de test distorsionaría las métricas: el MAPE de esos 5 días no es comparable con el MAPE de un mes completo. El umbral de 20 días garantiza que cada "mes de test" representa un periodo razonablemente completo.

¿Por qué no hay split de validación separado como en los árboles?
En los modelos de árboles (XGBoost, Random Forest) el tuning necesita un set de validación independiente porque los modelos tienen muchos hiperparámetros que interactúan y es fácil sobreajustar al conjunto de validación. En los modelos ARIMA, el espacio de parámetros es mucho más pequeño (p, d, q, P, D, Q son números pequeños) y el tuning se hace con walk-forward CV: en cada fold se usa toda la historia anterior al mes del fold como train, y se predice ese mes. Esto ya es validación robusta interna, sin necesidad de un split externo.

Sección 6

Funciones auxiliares Celda 13

Hay cuatro funciones centrales. Cada una tiene un propósito muy específico.

① compute_metrics — Calcular MAE, RMSE, MAPE y R²

métricas
def compute_metrics(y_true, y_pred):
    mae  = mean_absolute_error(y_true, y_pred)
    rmse = np.sqrt(mean_squared_error(y_true, y_pred))
    mask = y_true != 0
    mape = np.mean(np.abs((y_true[mask] - y_pred[mask]) / y_true[mask])) * 100
    r2   = r2_score(y_true, y_pred)
    return {'MAE': mae, 'RMSE': rmse, 'MAPE (%)': mape, 'R²': r2}
MétricaFórmula intuitivaInterpretación para tu caso
MAEPromedio de |error| en kWhSi MAE = 500 kWh, el modelo se equivoca en promedio 500 kWh por día
RMSERaíz del promedio de error²Penaliza más los errores grandes. Útil si un día de error enorme es inaceptable
MAPEPromedio de |error| / real × 100Error en porcentaje. Un MAPE del 3% significa que el modelo se equivoca el 3% del consumo real. Facilita comparar meses con distinto nivel de consumo
R²Varianza explicada por el modeloR²=0.9 → el modelo explica el 90% de la variación del consumo. R²<0 → peor que predecir la media

El mask = y_true != 0 evita divisiones por cero en el MAPE para días donde el consumo registrado sea exactamente cero.

② build_model — Construir el objeto del modelo

build_model
def build_model(model_name, order, seasonal_order=None):
    if model_name == 'ARIMA':
        return ARIMA(order=order)           # (p, d, q)
    else:  # SARIMA / SARIMAX
        return ARIMA(order=order,            # (p, d, q)
                     seasonal_order=seasonal_order)  # (P, D, Q, m)

Nota que SARIMA y SARIMAX usan el mismo objeto ARIMA de pmdarima con seasonal_order activo. La diferencia entre ellos no está en la construcción del modelo sino en si le pasas las variables exógenas al .fit(). El objeto no sabe si es SARIMA o SARIMAX hasta que lo entrenas.

③ fit_predict_model — Ajustar y predecir

fit_predict
def fit_predict_model(model_name, order, seasonal_order,
                      y_tr, X_tr, y_te, X_te):
    m = build_model(model_name, order, seasonal_order)
    if model_name == 'SARIMAX':
        m.fit(y_tr, X=X_tr)                       # ← pasa exógenas al train
        preds = m.predict(n_periods=len(y_te), X=X_te)  # ← y al predecir
    else:
        m.fit(y_tr)                                # ARIMA/SARIMA: solo la serie
        preds = m.predict(n_periods=len(y_te))

n_periods=len(y_te) le dice al modelo cuántos pasos adelante predecir. Si el mes de test tiene 30 días, se hacen 30 predicciones hacia adelante a partir del último dato de entrenamiento.

Predicción multi-paso vs un-paso
Esta función hace predicción multi-paso: el modelo se ajusta una vez y predice todos los días del mes de un golpe. Cada predicción del día N usa las predicciones del día N-1 como entrada (no el valor real). Esto es más realista para un escenario de operación real donde no se conoce el consumo del día anterior. Produce mayor error que la predicción un-paso, pero es más honesto.

④ cv_score_arima — Walk-Forward CV

walk-forward CV
def cv_score_arima(model_name, order, seasonal_order, cv_months):
    mapes = []
    for mes in cv_months:
        cutoff = pd.Timestamp(f'{mes}-01')
        end    = cutoff + pd.offsets.MonthEnd(1)
        tr  = df[df.index < cutoff]       # todo ANTES del mes
        val = df[(df.index >= cutoff) &   # el mes completo
                  (df.index <= end)]
        # → ajusta, predice, calcula MAPE
    return float(np.mean(mapes))

Esta es la función más importante del tuning. Para cada combinación de hiperparámetros (p, d, q…), en lugar de ajustar una vez, se ajusta N_CV_FOLDS veces. En cada fold:

  1. Train = todo el dataset hasta el inicio del mes de CV
  2. Validación = ese mes completo
  3. Se calcula el MAPE de ese fold

El score final es el MAPE promedio sobre todos los folds. La combinación de parámetros con menor MAPE promedio gana. Esto es walk-forward porque en cada fold el train se expande hacia adelante.

Sección 7

Espacios de hiperparámetros y defaults Celdas 15–17

Se definen tres cosas: la grilla de búsqueda, los parámetros por defecto (baseline), y una opción de muestreo aleatorio.

param grid
PARAM_GRID = {
    'p': [0, 1, 2, 3],  'd': [0, 1],  'q': [0, 1, 2, 3],
    'P': [0, 1, 2],    'D': [0, 1],  'Q': [0, 1, 2],
}

GRID_ARIMA = list(itertools.product(p, d, q))  # todas las (p,d,q)
GRID_SAR   = list(itertools.product(p,d,q,P,D,Q)) # todas las (p,d,q,P,D,Q)

# Filtrar combinaciones nulas
GRID_ARIMA = [(p,d,q) for ... if p+q > 0]
GRID_SAR   = [(p,d,q,P,D,Q) for ... if (p+q > 0 or P+Q > 0)]

itertools.product genera el producto cartesiano. Con p∈{0,1,2,3}, d∈{0,1}, q∈{0,1,2,3} tenemos 4×2×4 = 32 combinaciones para ARIMA. Para SARIMA/SARIMAX añadimos P∈{0,1,2}, D∈{0,1}, Q∈{0,1,2}: 32 × 3×2×3 = 576 combinaciones. Por eso existe el muestreo aleatorio.

muestreo aleatorio
SAMPLE   = True    # activa muestreo si la grilla es muy grande
N_SAMPLE = 40     # evalúa solo 40 combinaciones aleatorias

if SAMPLE:
    idx_a = rng.choice(len(GRID_ARIMA), N_SAMPLE, replace=False)
    GRID_ARIMA = [GRID_ARIMA[i] for i in idx_a]  # submuestra aleatoria
¿Cuándo activar SAMPLE = True?
La grilla completa de SARIMA/SARIMAX puede tener ~500 combinaciones × 6 folds CV = 3000 ajustes de modelo. Con datos diarios de 6 años cada ajuste tarda varios segundos. Activa el muestreo para una exploración rápida. Una vez que sabes en qué región del espacio están los buenos parámetros, puedes acotar la grilla y hacer búsqueda exhaustiva.

Los parámetros por defecto sirven como baseline: un ARIMA(2,1,2) es un punto de partida razonable para series económicas/de consumo. La comparación Default vs Tuneado al final del notebook muestra cuánto ganaste con el tuning.

Sección 8

Grid Search + Walk-Forward CV — El tuning Celda 19

Esta es la celda más costosa computacionalmente. Itera sobre cada combinación de parámetros, la evalúa con CV, y guarda el mejor resultado.

grid search principal
for model_name in MODELS:          # ARIMA, SARIMA, SARIMAX
    grid = GRID_ARIMA if model_name == 'ARIMA' else GRID_SAR

    for i, combo in enumerate(tqdm(grid)):
        if model_name == 'ARIMA':
            p, d, q = combo
            order = (p, d, q);  seasonal_order = None
        else:
            p, d, q, P, D, Q = combo
            order = (p, d, q);  seasonal_order = (P, D, Q, SEASONAL_M)

        score = cv_score_arima(model_name, order, seasonal_order, CV_MONTHS)
        rows.append({'cv_mape': score, ...})

El flujo para cada combinación es:

  1. Desempacar los parámetros del combo (p, d, q) o (p, d, q, P, D, Q)
  2. Llamar a cv_score_arima() que internamente hace N_CV_FOLDS ajustes
  3. Guardar el MAPE promedio de CV en rows
  4. Al final, ordenar por MAPE y tomar la primera fila → mejores parámetros
¿Por qué MAPE como métrica de tuning y no RMSE?
El MAPE es adimensional (está en %) y comparable entre meses con distinto nivel de consumo absoluto. El RMSE en kWh depende del nivel de consumo: un RMSE de 800 kWh puede ser excelente en verano (alto consumo) y pésimo en invierno. Para el tuning necesitas una métrica que sea justa en todos los folds, y el MAPE lo consigue.

Resultados del tuning — Convergencia Celda 21

Esta gráfica muestra cómo evoluciona el MAPE CV a medida que se van evaluando más combinaciones. Cada punto es una combinación (p,d,q) o (p,d,q,P,D,Q). La línea discontinua negra es el mínimo acumulado: una vez que se encuentra una buena combinación, la línea baja y se queda ahí.

Cómo interpretar la gráfica de convergencia
Si la línea de mínimo acumulado sigue bajando al final de la búsqueda, significa que el espacio de búsqueda está recortado y probablemente hay combinaciones mejores fuera de tu grilla. Si se estabiliza pronto, la grilla es suficiente. Idealmente la línea baja rápido al principio y luego se aplana → la búsqueda fue eficiente.

¿Qué modelo elegir para tu estación?
Como regla general para consumo eléctrico con patrón semanal claro: si las variables exógenas (festivos, mantenimientos) tienen impacto visible en la serie, SARIMAX debería ganar. Si el impacto es pequeño o ruidoso, SARIMA puede ser más estable. ARIMA puro sirve como referencia pero rara vez gana en datos con estacionalidad fuerte. El heatmap de la sección 15 y las barras agrupadas de la sección 17 te darán la respuesta definitiva con tus datos reales.
